1. **Адрес API**: `https://lizh.ai/v1`

## Установка Hermes Agent

### macOS, Linux или WSL2

Запустите официальный установщик Hermes в терминале:

```bash
curl -fsSL https://hermes-agent.nousresearch.com/install.sh | bash
```

### Windows

Выполните следующую команду в PowerShell:

```powershell
iex (irm https://hermes-agent.nousresearch.com/install.ps1)
```

После установки откройте новое окно терминала и проверьте версию:

```bash
hermes version
```

Если появилась информация о версии, Hermes установлен успешно.

## Настройка <WebsiteName />

Hermes рекомендует добавлять пользовательский OpenAI-совместимый адрес через мастер настройки моделей.

### 1. Откройте мастер настройки моделей

Выполните в терминале:

```bash
hermes model
```

### 2. Выберите пользовательский адрес

В списке Provider выберите:

```text
Custom endpoint (self-hosted / VLLM / etc.)
```

Точное название пункта может немного отличаться в разных версиях. Выберите вариант, содержащий **Custom endpoint**.

### 3. Введите данные подключения

Следуя подсказкам мастера, укажите:

| Параметр | Значение |
| --- | --- |
| API base URL | `https://lizh.ai/v1` |
| API key | Создайте и скопируйте API-ключ на странице [Управление API-ключами](https://lizh.ai/keys) |
| Model name | Найдите и скопируйте точное название модели в [каталоге моделей](https://lizh.ai/pricing), например: `glm-5.2` |

Если мастер запросит Context length, укажите размер контекста, показанный для выбранной модели. Если вы не уверены, оставьте значение по умолчанию, предложенное Hermes.

После завершения Hermes сохранит модель, Provider и адрес API в `~/.hermes/config.yaml`. Настройки сохранятся после перезапуска терминала.

<Callout type="warning" title="Для первой настройки используйте hermes model">
  `hermes model` — полный мастер настройки в терминале, который позволяет добавить Provider, адрес API и API-ключ. Команда `/model` внутри чата Hermes может только переключать уже настроенные Provider и модели.
</Callout>

## Проверка подключения

Выполните:

```bash
hermes chat
```

После запуска чата отправьте простое сообщение. Если Hermes вернул ответ, адрес API, API-ключ и ID модели настроены правильно.

Чтобы позднее сменить модель <WebsiteName />, завершите текущий сеанс и снова выполните:

```bash
hermes model
```

## Ручная настройка (необязательно)

Если интерактивный мастер недоступен, отредактируйте файл `~/.hermes/config.yaml`:

```yaml
model:
  default: "ID модели из каталога моделей"
  provider: custom
  base_url: https://lizh.ai/v1
  api_key: "ваш API-ключ lizh.ai"
```

Сохраните файл и снова запустите `hermes chat`. Для отступов в YAML используйте пробелы, а не Tab. Не публикуйте конфигурационный файл с настоящим API-ключом в открытом репозитории.

## Частые проблемы

### Ошибка 401 или Authentication failed

API-ключ недействителен, истёк или скопирован не полностью. Проверьте состояние ключа в разделе управления API-ключами <WebsiteName /> и при необходимости создайте новый.

### Ошибка 404, Model not found или модель недоступна

ID модели должен полностью совпадать с названием в каталоге моделей <WebsiteName />. Проверьте регистр, дефисы и номер версии.

### Не удаётся подключиться к API

Убедитесь, что API Base URL указан как `https://lizh.ai/v1` и содержит `/v1` в конце. Также проверьте, доступен ли <WebsiteName /> из вашей сети.

### <WebsiteName /> не отображается в `/model`

Завершите чат Hermes и выполните `hermes model` в системном терминале, чтобы сначала настроить пользовательский адрес. После этого команду `/model` можно использовать внутри чата для переключения моделей.

### Ошибка `hermes: command not found`

Закройте и снова откройте терминал. Если команда по-прежнему недоступна, проверьте путь установки и настройку `PATH` по официальной инструкции Hermes: [FAQ & Troubleshooting](https://hermes-agent.nousresearch.com/docs/reference/faq).
